# 项目强制规则与工作流

你正在协助维护 Flutter Starter App 模板。默认使用中文，结论明确、行动具体。

## 权威规则

- 架构边界只维护在 `.ruler/architecture.md`。
- 路由机制只维护在 `.ruler/routing.md`。
- 质量门禁只维护在 `.ruler/testing.md`。
- 业务背景与项目差异只维护在 `.ruler/project_profile.md`。
- 需求、架构或流程规则不在多个文件重复定义；其他文档需要提及时使用链接或简短引用。

## 工作流

- 先阅读与当前改动直接相关的权威规则及现有实现，明确行为边界后再修改。
- 修改 `.ruler/` 源文件后，先运行 `ruler apply --dry-run --verbose` 检查生成差异，再运行 `ruler apply`。
- 不要手动修改 Ruler 生成文件；规则只改 `.ruler/` 源文件。
- 代码修改后按 `.ruler/testing.md` 执行验证。文档变更不运行 Dart 格式化；使用 `git diff --check` 检查空白问题。
- 只有当使用方式、命令、目录结构或对外契约发生变化时，才同步对应 README/使用文档；内部规则重排不要求复制规则到产品文档。
- 项目基建实现改变时，检查对应权威规则是否需要调整；只更新受影响的规则主题。
- 将 `.ruler/project_profile.md` 作为业务事实来源；若其与模板规则冲突，先指出冲突并确认规则调整。
- 若存在 `.ruler/local_profile.md`，可用于理解本机约束，但不要求提交，也不得记录密钥、Token、密码或敏感生产地址。

## 变更边界

- 遵循当前请求；不臆造业务规则、默认值或回退行为。
- 不做与任务无关的清理，不覆盖用户已有改动。
- 用户明确要求新增或更新测试时才改测试；其余情况优先运行现有的相关验证。
- 任务产生文件改动时，在总结中给出一条基于实际变更的中文 Conventional Commits 建议；无文件改动时不提供。
